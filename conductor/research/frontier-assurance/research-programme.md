# From a measured foundation to frontier research

Status: prospective programme, 13 November 2026. The words frontier and beyond frontier are evidence-dependent aims. Existing negative results, unsupported models and incomplete historical studies are preserved.

## Stage 1: Demonstrate useful components

Implement D0–D3 with no model dependency, then compare rules/NLP against admitted local models on D4. The initial product is a source-linked, uncertain chronology and decision-time evidence packet. CAW02/04/08/10/20 remain the executable scientific leaves. The three audited integrity/template/export defects are repaired first. An honest useful component is deliverable even if no generative system qualifies.

## Stage 2: Establish a frontier comparison

The primary question is whether the staged system reduces severity-weighted unsupported assertions and material omissions at useful coverage, compared with the best relevant baseline under the same admissible evidence and resource conditions. Freeze the loss weights, minimum useful coverage, improvement margin and precision/sample-size target after development and before test unblinding. Do not retrospectively choose the winning metric.

Compare a competent prompt using the same model; the portable skill; deterministic and classical NLP baselines; an optional compact encoder; a generator-plus-verifier pipeline; and a selective multi-model/multimodal arm only when individually admitted. Distinguish the effect of the skill, model, retrieval, tools, staged verification and additional compute through ablations. Record the actual local model tuple, not only a family name.

Data sources include generated synthetic oracle cases, an admitted HDC snapshot, and a separately eligible external public comparator such as RO-ILS. Public availability does not imply redistribution rights. Group by incident/case family, duplicate/version and rendering family; preserve temporal holdouts. Final published findings and later outcomes are isolated from decision-time analysis. Study case counts are based on admissible inputs and planned precision, not invented from repository file counts.

Report component and end-to-end results, material error types, selective risk/coverage, calibration, patient/family concern fidelity, recommendation quality and failure denominators. Case-clustered intervals avoid pseudoreplication from repeated seeds or edited versions. Freeze reference labels and record reviewer class, disagreement and adjudication. Agent panels continue engineering review; human workflow or clinical claims require observations of those processes.

An external dataset/task/configuration can qualify only its declared scope. Cross-jurisdiction generalisation and operational approval are separate. Use the existing Inspect AI candidate through a thin adapter for runs/logs/scorers where it removes custom harness maintenance; preserve rcagent's domain/view/admission invariants [R4].

## Stage 3: Beyond-frontier hypotheses

| Hypothesis | Experiment | Comparison and falsifier |
| --- | --- | --- |
| Availability-aware analysis reduces hindsight without suppressing useful new evidence | Paired outcome-masked/exposed and evidence-availability interventions, independently executed | Beats strongest context-matched baseline on both outcome invariance and appropriate cue sensitivity; otherwise reject |
| Explicit source/method dependence improves corroboration | Compare origin-aware discrepancy handling with naive voting and a single strong verifier | Lower material error at fixed coverage/cost; shared errors and new omissions must be reported |
| Preserving uncertainty improves process-based interpretation | Interval/partial-order traces versus forced point-time traces through admitted process engines | Better reference-consistent conclusions and fewer unwarranted error labels; process deviation alone is not unsafe care |
| Active evidence questions improve decisions efficiently | Random/heuristic questions versus uncertainty- or value-informed acquisition | Reduced supported error/loss per fixed evidence/reviewer budget; a formal VOI claim requires admitted priors, likelihoods and utilities |
| Stronger recommendation mechanisms improve learning | Link supported factors to interventions, feasibility, balancing measures and observed follow-up | Better action quality/implementation and measured outcomes in an appropriate design; text similarity cannot establish patient benefit |
| A qualified system transports and detects its own limits | External source, jurisdiction, specialty, hardware and time-period replication | Maintained declared risk/coverage or useful calibrated abstention; automatic qualification on a new domain is prohibited |

Each experiment has a protocol, frozen comparison, stop rule and explicit null/negative result path. Synthetic mechanism recovery establishes performance under its generative assumptions; it does not identify real-world causes without suitable evidence. Fine-tuning/LoRA is a conditional residual-error experiment, not a mandatory milestone. Preserve the best simpler system when adaptation or extra agents fail.

## Demonstration versus practice

Development evaluates code and candidate error discovery. Verification evaluates the verifier itself and the full pipeline. Practice evaluates how an accountable reviewer uses supported output, disagreement and missing evidence. These are different outcomes. The initial practice-facing artifact is an inspectable evidence/timeline packet and review queue; any wider deployment requires the exact local security and organisational authority applicable to it.

## Delivery cadence and governance

Use one integration lane plus two independent implementation lanes. Each task has bounded context, file ownership, exact inputs, a command and an evidence receipt; no standing requirement for a large committee or external engineer. Continue automatically through tests, agent review and in-scope rework. Escalate only new reserved scope once; an existing HDC approval is not re-requested. Hardware/data-dependent execution may wait while synthetic/engineering work continues.

Publish software, datasets, models or a paper only under their existing exact-scope authority. Planning does not authorise copying restricted records to GitHub or sending source data to model providers. No arbitrary calendar date is promised for frontier status.
