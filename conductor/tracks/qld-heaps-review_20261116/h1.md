## Minimal consumer interface proposal

This is a scoped HEAPS proposal over observed existing APIs, subject to independent review and receiving agreement. It does not assert an upstream-owner acknowledgement, change a public API or allocate shared files. H3 must still freeze the executable profile schema and H4 must prove the composed boundary.

| Boundary | Existing interface | HEAPS consumer requirement |
| --- | --- | --- |
| Canonical case | `tools.evidence_core.validate_record` and `canonical_round_trip`; `safety-work.schema.json` | Consume schema 1.1 and bind `case_id`, integer `version` and content identity. Keep HEAPS metadata outside the closed canonical object. Domain validation precedes any rendering. |
| Canonical identity | `tools.evidence_core.canonical_bytes` / `fingerprint` | The core digest uses sorted compact JSON, unescaped Unicode encoded as UTF-8, and `sha256:` notation. Preserve array order. This hashes the supplied record; it does not verify referenced source bytes. |
| View identity | `tools.interface_actions.canonical_hash` / `render_view` | The renderer uses a bare hexadecimal digest of JSON with ASCII escapes. Compute this independently from the same validated payload; never translate the core digest by removing its prefix. Keep algorithm/domain labels explicit. |
| Participation | `tools.interface_actions.validate_participation` | Retain its generated-synthetic admission boundary and account/confirmation semantics. Link accounts and role identities; the HEAPS process must separately distinguish participation, review and authority. |
| Approval | `tools.interface_actions.validate_approval` | Existing scopes are finding, action, effectiveness, closure and communication. An invented `heaps_packet` scope is rejected. Agree the packet mapping with the shared owner; communication approval cannot stand for every substantive review decision. The helper checks declared fields and time, not actual human identity or authority. |
| Recommendations and actions | `validate_recommendation` / `transition_action` in `tools.interface_actions` | These APIs require richer recommendation records than canonical actions. Define a lossless mapping and supply the actual evaluation time rather than their historical default. A rendered action list is not evidence of implementation or effect. |
| Jurisdiction | `tools.jurisdiction_pack.load_registry` / `validate_registry` / `compare_snapshots` | Reuse canonical source IDs and drift semantics. Do not activate this planning source inventory as a second rules registry. |
| Templates | `tools.template_admission.validate_template_admission` | New original rendering assets need admission in the existing manifest after H2 review. Admission checks bytes and declared status; it cannot grant rights to an official form. |
| Optional components | Accepted D0 and AcciMap contracts | Do not consume draft status as acceptance. Their absence removes their specific capability; it does not mandate another implementation or block all HEAPS preparation. |

HEAPS process, selected analytical tools, review scope, commissioning and protection status remain distinct. The profile references canonical accounts, statements, factors, actions and reviews. Factor taxonomy is separate from factor function. Preparation, structure, source verification, local mapping, authorised review and external submission remain separate dimensions. A detached manifest and separately stored approval avoid circular hashing. These are rcagent design requirements, not an assertion that Queensland mandates this software schema.
