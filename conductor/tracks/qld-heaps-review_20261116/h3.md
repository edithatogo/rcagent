# H3 — Profile contract and independent fixture receipt

Status: implemented and independently reviewed on the HEAPS branch. This is the
contract/fixture checkpoint, not H4 packet assembly or H5 runtime qualification.
The user explicitly authorised H2/H3; coordinator integration and merge remain
separate.

## Delivered contract

[The normative contract](./h3-contract.md) and four standalone, closed schemas
freeze the profile, detached packet manifest, synthetic draft decision and status
receipt. The canonical safety-work 1.1 model is unchanged. Profile references
identify both the entity kind and exact bound case/revision, including statement
subkinds for accounts, findings, recommendations and decisions.

The contract makes the following distinctions executable at schema level where
possible and explicit future consumer obligations where cross-record checks are
needed:

- Case identity versus profile identity, raw artifact bytes versus compact
  canonical UTF-8 fingerprints versus ASCII-escaped interface hashes.
- Incident involvement versus review responsibility; participation opportunity,
  account confirmation, disagreement and approval.
- Factor function versus a versioned taxonomy mapping; source copies versus
  independent source families; support versus contrary evidence and alternatives.
- Occurrence, document and availability times; awareness, SAC1 reporting and
  submission triggers; source/calendar/timezone/counting convention versus an
  unresolved deadline. No operational deadline is computed by H3.
- Preparation, structural checking, source-check scope, template mapping,
  synthetic review and submission. Submission and actual authority remain
  unestablished for this synthetic-only version.
- Action implementation versus outcome/balancing evidence and effectiveness.

The construction order is acyclic. Fixed input identities precede the report;
raw artifact hashes precede the detached manifest; the later decision binds the
manifest; the status receipt can observe those earlier artifacts. Nothing inserts
a later approval or self-hash back into the artifact it identifies. Changes
invalidate affected bindings and require a new review, while preserving history.

The decision scope is `heaps-synthetic-draft-packet`. It is a separate synthetic
contract, not an added shared approval scope or automatic communication approval.
It does not approve findings, actions, closure, statutory protection or live use.

## Review findings resolved before freezing

Independent review corrected three substantive fixture arrangements:

1. Replacing template bytes under old bindings now rejects input and marks prior
   review stale, just as a source-byte substitution does. A legitimately rebound
   new template is a separate arrangement; no silent repair is rewarded.
2. All-abstain now derives from all seven canonical statements being withdrawn,
   with related factor/action/review states retained as withdrawn. Empty and
   all-abstain counts are 0/0/0 and 7/0/7. Supplied status specimens are explicitly
   non-input illustrations and have correct profile bindings.
3. The method-change variant includes a source and canonical decision recording
   handover from a fictional prior process to HEAPS. Existing clocks remain
   unchanged. Migration of another production profile is not claimed.

The normative count rule also includes both the canonical `withdrawn` Boolean
and rejected/withdrawn provenance states. Usable draft-item counts do not measure
clinical truth, findings accepted or review quality.

Root review corrected canonical ID grammar, incident-involvement fields,
versioned source/calendar metadata, supporting-artifact coverage, source-check
scope, stale review and explicit participation missingness. These changes remain
inside the dedicated profile; no shared canonical field or public API was added.

## Verification and limitations

The H3 suites passed **101 checks**: 52 schema structural checks and 49 independent
fixture-design checks. A reviewer who authored none of the H3 files independently
ran the combined suite and inspected the corrected arrangements, manifest bytes
and input hashes. The integrated locked checks and exact component inventory are
recorded in [h2-h3-review.md](./h2-h3-review.md).

JSON Schema does not validate actual referenced targets, source truth, real dates,
calendar applicability, reviewer identity, raw hashes or causal support. Tests
explicitly demonstrate those structural limits instead of concealing them behind
a passing schema result. H4 must enforce the normative consumer rules; H5 must
execute the actual public interface and subprocess against the frozen independent
expectations. No H3 test count is reported as clinical or composed-runtime
qualification.

D0 is accepted upstream at the reconciled master. Optional HEAPS span composition
still needs an exact input/component receipt, including the current lock. The
shared renderer and missing date-time enforcement observed in H1 remain unchanged;
canonical admission and strict time guards or accepted shared repairs remain
H4 requirements. Official local form/taxonomy/rights alignment remains H6.
