# Track 08 fit-gap record

## Outcome

Track 08 will adapt existing runtime and evaluation contracts rather than build
an inference engine, model manager, downloader or provider abstraction. The
small project-owned gap is privacy-safe discovery, strict admission,
fail-closed routing, operator-owned bundle verification and recommendation
evidence.

## Existing systems and measured fit

| Capability | Existing system | Repository observation | Selected intervention |
|---|---|---|---|
| Generation comparator | Track 05 `llama.cpp` adapter | exact local research-only comparator admission exists; all comparator recommendations were unsupported | reuse and harden admission; do not promote |
| Evaluation | Track 05 deterministic harness | synthetic cases and fixed hashes pass | reuse fixtures and receipts |
| Multimodal disclosure | Track 06 capability contracts | model-backed adapters remain unsupported | reuse disclosure states |
| Retrieval | Track 07 SQLite lexical profile | deterministic lexical profile passes; embeddings and reranking unsupported | retain lexical fallback |
| Optional runtimes | llama.cpp, ONNX Runtime, OpenVINO, MLX/MLX-LM | no Track 08 exact execution receipt | thin contracts and explicit unavailable/unmeasured states |
| Experimental runtime | MAX/Mojo | terms, runtime and device fit unverified | isolated experimental negative state |

## Boundaries and lifecycle

- Portable core: Python standard library and JSON contracts only.
- Optional adapters: independently discoverable and replaceable; absence is non-fatal.
- Network and telemetry: discovery does not use them. A declaration is not enforced isolation.
- Data: generated synthetic and public metadata only; no private clinical or employee data.
- Models: roadmap names are hypotheses, not admitted model entries. Exact immutable revisions, licence evidence, provenance and device receipts are required for admission.
- Offline bundles: verify an operator-owned inventory only; do not copy, download, redistribute or delete model bytes.
- Safe fallback: explicit `no_capability`; never a remote fallback.
- Removal: delete an optional profile or replace its adapter behind the contract without changing portable-core semantics.

No upstream issue is needed: the gap is project-specific governance and
admission logic, not missing inference functionality.
