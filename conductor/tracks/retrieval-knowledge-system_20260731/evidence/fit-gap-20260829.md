# Track 07 fit-gap checkpoint

## Selected systems

SQLite FTS5 provides the deterministic lexical baseline. The local runtime is
SQLite 3.53.4 with FTS5 enabled through Python 3.14.7. The project owns only a
thin retrieval port, corpus and query contracts, compartment enforcement,
provenance, grounding, lifecycle controls and assurance receipts.

The existing SourceRight subprocess adapter remains the citation-integrity
boundary at vendored pin `c5fa583`. It is optional and fail-closed. Literature
providers, Haystack, LlamaIndex, Qdrant, LanceDB, FAISS, encoder models and
rerankers were assessed as replaceable candidates, not portable-core
dependencies.

## Negative findings

Track 06 admitted no encoder or cross-encoder model. Vector, hybrid and model
reranking profiles therefore remain unsupported. No external literature
provider, private corpus, enterprise connector, cross-compartment query,
remote embedding service or operational threshold was enabled. Typo
correction is also unsupported by the exact FTS baseline.

## Lifecycle

The exact schema 1.0 and SQLite FTS5 contract are the compatibility window.
Any schema, SQLite feature, source checksum, SourceRight contract or optional
profile change requires revalidation and rebuild. The safe fallback discards
the derived index, rebuilds from validated manifests and retains the
single-compartment lexical profile. Generic provider or framework gaps belong
upstream; this adapter expires when a maintained equivalent preserves the same
fail-closed contracts.
