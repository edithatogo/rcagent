# Track 11 Distribution Fit-Gap

This record defines the smallest repository-owned distribution boundary before any public release or submission.

## Existing systems

| Capability | Existing owner | Repository use | Boundary |
|---|---|---|---|
| Portable skill format | Agent Skills specification and its pinned Track 00 baseline | Keep `skills/rca-investigation/` client-neutral | No project-owned skill format or universal-registry claim |
| Source distribution | Git and GitHub release artefacts | Prepare deterministic local archives and reviewable manifests | Creating a release is a separate owner decision |
| Client discovery | Each client's documented skill or plugin mechanism | Thin declarative adapters copy the unmodified portable core | No client permissions are embedded in the core |
| Supply-chain metadata | SPDX and CycloneDX formats plus hosting-platform attestations | Emit local checksums and CycloneDX metadata | Signing, attestation, and publication require a separately authorised release |
| Marketplace discovery | Client-owned or community-operated directories | Record a dated assessment and dry-run submission packet | Publisher verification and submission remain owner gates |

## Selected intervention

The repository owns only deterministic local packaging, thin adapter manifests,
compatibility tests, and decision-ready submission evidence. It does not own a
registry, marketplace, updater service, signing authority, plugin runtime, or
duplicate copy of the portable skill.

The local package builder:

- reads only the portable skill and root Apache-2.0 licence;
- rejects symlinks and non-empty destinations;
- uses stable archive metadata and sorted paths;
- emits per-file and archive SHA-256 checksums;
- emits reviewable CycloneDX metadata;
- performs no network access, installation, signing, release, or submission; and
- declares that the result is not a public release.

## Dependency lifecycle

| Dependency class | Contract | Drift and failure response | Replacement path |
|---|---|---|---|
| Locked portable core | Track 00 completion receipt and conformance suite | Fail package validation when source or licence is missing | Rebuild from the last passing portable-core revision |
| Client adapters | `adapters/*/adapter.json` plus isolated-copy tests | Mark unsupported on discovery or compatibility drift | Update or remove the thin adapter without changing the core |
| Distribution formats | Deterministic ZIP, SHA-256 manifest, CycloneDX JSON | Preserve the last verified build and require review | Replace a format behind the same local build contract |
| Hosting and directories | Evidence-only candidate records | Treat unavailable or changed guidance as unverified | Retain Git source installation or another reviewed route |

## System-of-record boundary

Git history and Conductor receipts are the repository evidence sources. A
hosting platform is authoritative only for an observed release, submission,
review, or acceptance event. Local archives and green tests never imply any
such external event.

## Removal and rollback

Delete an unshared local output directory or revert the focused Track 11
commits. Published artefacts, if ever authorised, require a release-specific
rollback and supersession plan; this track does not pre-authorise deletion or
revocation on a hosting service.
