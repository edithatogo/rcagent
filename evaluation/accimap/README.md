# AcciMap synthetic companion

This adapter binds an explicitly authored AcciMap to one canonical safety-work
1.1 record and renders a deterministic Mermaid draft. The portable
[facilitation guide](../../skills/rca-investigation/references/methods/accimap.md)
covers the investigation process; the
[Conductor contract](../../conductor/tracks/accimap-workflow_20261116/contract.md)
defines the executable boundary.

## Run the example

From the repository root, with the locked `validate` dependencies installed:

```bash
python -m tools.accimap validate tests/fixtures/accimap/graph.json \
  --record tests/fixtures/accimap/record.json

python -m tools.accimap render tests/fixtures/accimap/graph.json \
  --record tests/fixtures/accimap/record.json
```

`validate` prints JSON and exits zero for a structurally valid draft. Read
`review_findings`, `review_state` and `outcome_paths` as well as
`structurally_valid`. The fixture intentionally contains unresolved analysis:

| Factor node | Expected path to the declared incident outcome |
|---|---|
| `node-policy` | A path whose edges are declared supported; an additional direct hypothesis remains uncertain |
| `node-queue` | A path whose edges are declared supported; the canonical factor is still a candidate |
| `node-availability` | A path containing a contested edge and conflicting accounts |
| `node-context` | No path; level remains unassigned |

`render` prints Mermaid source to stdout. Redirect it to a file if required; the
adapter itself writes no files. Both commands exit 2 on invalid input. The
committed [example diagram source](./synthetic-example.mmd) and
[inspection](./synthetic-inspection.json) were generated by these commands.

The fixture has one proposed action with effectiveness `not_due`, no declared
map review and no real incident data. Its
[README](../../tests/fixtures/accimap/README.md) records construction and oracle
provenance. Expected topology was specified independently of the traversal.

## Author and review a graph

1. Use a valid canonical record with `schema_version: "1.1"` and
   `system_of_record.kind: "generated-synthetic"`. This increment is qualified
   only for generated examples; a label cannot detect mislabelled private data.
2. Select `rcagent-healthcare-six-v1` for the existing repository adaptation, or
   `rasmussen-svedung-six-v1` for the original hierarchy. Review placements when
   changing profiles. Outcome is a node role independent of level.
3. Link nodes to existing statements and factors. Give every placement a
   rationale; use null for an unresolved level. Represented statements must
   resolve to sources and cannot come from excluded sources.
4. Author contributory edges explicitly. Canonical evidential `supports` and
   `contradicts` relationships are not automatically converted into causal
   connections. Preserve evidence IDs, conflicts, rationale and uncertainty.
5. Link canonical recommendations to the graph elements they address, explain
   the proposed mechanism and reference their canonical actions. Missing
   recommendations/actions remain review findings, not fabricated defaults.
6. Bind the graph to the record's exact case ID, integer version and canonical
   fingerprint. Use `tools.evidence_core.fingerprint(record)`; validate again
   after any change. The adapter never repairs stale bindings silently.
7. Inspect and discuss gaps, alternatives, placement and recommendations using
   the method guide. Review metadata may be attached to the exact
   `graph_fingerprint(graph)`, which excludes the `review` field itself.

Review metadata is a declaration, not authentication or approval. An otherwise
valid withdrawn record can be rendered for inspection with its case state
visible; withdrawn/rejected statements, factors and evidence cannot be used as
active graph material. Linked action status and effectiveness remain visible.

## Python interface

```python
from tools.accimap import (
    graph_fingerprint,
    inspect_accimap,
    render_mermaid,
    validate_accimap,
)

errors = validate_accimap(graph, record)
inspection = inspect_accimap(graph, record)
diagram = render_mermaid(graph, record)  # ValueError on invalid input
review_identity = graph_fingerprint(graph)
```

The JSON schema is [accimap.schema.json](./accimap.schema.json). Structural and
semantic reference checks are both required; JSON-schema validation alone is
insufficient. Unknown fields, duplicate identifiers, ambiguous JSON, stale
bindings and invalid references fail. Multiple paths/outcomes, skipped levels,
same-level connections and cycles across distinct nodes are supported. The
bounded traversal terminates without treating a path as proof of causation.

The renderer generates safe internal identifiers and encodes labels. It keeps
the chosen profile, declared statuses, uncertainty, gaps and record/graph
identities. Mermaid clients control their own layout and security settings;
the source is deterministic, not a promise of identical pixels in every client.
Empty profile levels are omitted from the drawing and must still be considered
in the facilitated analysis. Annotation boxes are review material, not causal
nodes. Use the JSON record and graph alongside the diagram for the complete
provenance and action record.

python -m pytest -q tests/test_accimap.py

See the track's [verification receipt](../../conductor/tracks/accimap-workflow_20261116/verification.md)
and [review record](../../conductor/tracks/accimap-workflow_20261116/review.md)
for actual results, repairs, source identities and limits. The standalone CLI
does not alter the workbench/D0 extraction entry point, canonical schema or
legacy admitted Mermaid template. Connecting it to model output, real cases,
shared dispatch or a new portable release requires those existing owners and
qualification gates.
