# Security Policy

## Reporting a vulnerability

Use GitHub private vulnerability reporting when available. Do not put secrets,
credentials, patient or consumer information, employee information,
confidential material, internal paths, or organisation-sensitive evidence in a
public issue, pull request, screenshot, fixture, or log.

If private reporting is unavailable, open a public issue containing only a
sanitised description and request a private contact channel. Do not include
exploit material or controlled data.

## Scope and response boundary

Supported security claims are limited to exact released versions and repository
revisions with current receipts. Best-effort maintenance does not promise a
response time, availability, deployment suitability, regulatory compliance, or
clinical safety.

The repository must not contain private clinical or employee data,
third-party-controlled bytes without exact rights admission, credentials,
undisclosed network egress, or model-weight downloads. A report, patch, passing
test, or release does not constitute clinical, legal, policy, regulatory,
employment, cultural-safety, organisational, or deployment approval.
